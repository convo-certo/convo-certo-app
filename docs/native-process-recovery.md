# Macの画面プロセス終了から復旧する

Web Contentプロセスが終了した場合、ネイティブの「演奏画面が中断しました」画面で「画面を開き直す」「終了」を選べる。以前はアプリ全体を終了して再起動を求めていた。

開き直すとマイ楽譜へ戻り、保存済みの練習を選べる。未保存の変更や直前の演奏位置は戻らないことを説明する。ネイティブMIDIの接続を切り、再接続・発音・伴奏開始はユーザーの操作に委ねる。自動リロードを繰り返す処理にはしない。

## 実際の障害を使った検証

`npm run native:recovery`は専用の非永続データストアで次を実行する。

1. 自作MusicXMLを取り込み、伴奏のミュートを設定して練習を保存する。
2. CoreMIDI仮想入力を接続してノート受信を確認し、伴奏を開始する。
3. テスト開始後に現れ、Launch Servicesのアプリ名がConvoCerto Web Contentで、テスト用アプリと所属情報が一致するプロセスを一意に特定する。直前に同じ条件を再確認してSIGKILLを送る。候補がゼロ・複数・不明の場合は中止する。
4. 実際のWeb Content終了通知からネイティブ復旧画面が出ることを確認する。試験ではその画面の「画面を開き直す」ボタンをプログラムから押す。
5. 保存済み練習とミュート設定が残り、MIDI選択が空で、仮想送信元が音符を送っても未接続のまま届かず、マイク・伴奏が自動で開始しないことを確認する。
6. 保存済み練習を選んで演奏開始を押し、演奏位置が進むことを確認する。

`verify:release`と、DMGから一時フォルダーへコピーしたアプリのパッケージ検証にも含める。復旧検証を含まない古いレポートでは新しいDMGを梱包できない。通常の練習保存や他のアプリのプロセスは操作しない。プロセス終了を命令するWebブリッジや非公開WKWebView APIは追加していない。

## 残る範囲

保存処理の途中、印刷処理の途中、物理マイクを取得中、アプリ全体・OSの終了、ディスク破損、保存領域の削除は今回の実験では検証していない。未保存編集の自動復元は別機能。MacのOS・WebKitによる保存動作の差もあるため、対応OS全体の保証には実機別の確認が必要。

## 検証記録

2026-09-11の最終実行は `verification-results/2026-09-10T19-04-15.980Z/report.json`。単体221件・ブラウザ69件・通常の実WKWebView検証・実プロセス強制終了からの復旧が通過した。対象PIDと所属番号は `native-recovery.log` に記録した。

DMGからのコピーでも、同じ復旧試験が通過。DMG、パッケージレポート、`installed-recovery.log` は同じ検証フォルダーの `distribution/` に保存している。公証・一般配布への承認は未完了。
