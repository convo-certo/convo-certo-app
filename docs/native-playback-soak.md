# Swift / WKWebViewの実時間再生試験

`node scripts/soak-native.mjs 1800` で、ビルド済み `build/native/ConvoCerto.app` を `--soak-test --soak-seconds 1800` 付きで起動する。通常アプリは先に終了しておく。新たな開発サーバーは不要で、アプリ同梱のWeb画面とサンプルMusicXMLを使う。

試験モードは非永続のWKWebsiteDataStoreを使う。通常アプリの保存済み楽譜・練習を読み書きしない。既存のテスト用MIDIブリッジが初期化されるが、実機MIDIやマイクは接続しない。通常のアプリ起動では試験用スクリプトを実行しない。

使用するサンプル譜の冒頭には `wait:2sec` がある。したがってループには2秒の指定待機も含まれ、途中サンプルの表示が「合図を待っています」になる場合がある。表示だけで停止と判定せず、後続の時計と発音の進行を監視する。

## 検証すること

- 10秒ごとに実経過、AudioContext状態・時計、発音開始数、接続中の音源数、最大音源数、譜面位置を記録する。
- ページ例外、Promiseの未処理エラー、WebContent終了、時計停滞、新規発音停止、音源数上限超過を失敗とする。
- 指定秒数を終えた後も音源が接続中になるまで待ち、停止する。切断後の音源0・位置0・「準備完了」を確認する。
- 試験前後のソースとアプリバンドルのハッシュを照合する。ログと結果は `verification-results/native-soak-<日時>/` に逐次保存する。
- 指定時間は20〜7200秒。短すぎる／長すぎる値、数字以外、値欠落、他の試験モードとの併用の5条件を実コマンドで確認し、終了コード2で拒否された。

実時間を使うが、人の吹奏、マイクの認識、物理的な音声出力の遅延や波形、総譜全編成の密度は含まない。サンプル二重奏の1回を、発売条件の実演30分×20本に数えない。

## 最初に見つかった試験側の問題

`native-soak-2026-09-10T21-29-37.537Z` は20秒の再生後、「soak stop and release」の待機で失敗した。最初の観測は、startedを数え、endedイベントでだけ音源を集合から外していた。

音源の接続解除も観測した次の `native-soak-2026-09-10T21-31-01.019Z` は通過。発音開始28、ended通知25、引数なしdisconnectによる接続解除28。停止直前の接続中音源2が停止後0になり、表示と位置も復元した。切断された音源のended通知だけを終了条件にすると、試験側が切断済み音源を保持してしまうことが分かった。

現在の `active` は「start後、全接続解除またはendedのどちらも未観測の音源数」。`ended` と `disconnected` は別に記録し、両者を同一の数として扱わない。これはJSオブジェクトのGC完了やネイティブメモリの全解放を測った値ではない。失敗した初回レポートは保持している。

その後、停止直前の接続中音源が1個以上であることを明示的な条件に追加した。30分本試験でも、この条件を満たして停止できた。

## 現行版の実行

- 通常動作の一括検証: `verification-results/2026-09-10T21-31-42.805Z/report.json`。WebとSwiftの8工程が通過。
- 停止直前の接続確認を加えた20秒試験: `verification-results/native-soak-2026-09-10T21-33-47.318Z/report.json`。passed、停止直前2、停止後0。
- 30分本試験: `verification-results/native-soak-2026-09-10T21-34-12.803Z/report.json`。実プロセスは終了コード0、最終レポートはpassed。実観測1800.004秒、181サンプル、発音開始2171回、最大同時音源2。停止直前は接続中1、停止後0、位置0、表示「準備完了」。

同じフォルダーの summary.json に集計と元レポートのSHA-256を保存した。音声時計／実時間の区間比は0.999667〜1.000233。記録された例外は0。試験前後のソース・アプリバンドルハッシュが上記一括検証と一致した。

補助的なRSS観測は process-memory.jsonl に4回保存した。アプリと同じcoalitionのWebContentを確認して測定し、約15・20・27分時点のWebContent RSSは333472・333536・333696 KiBだった。開始直後の基準値、連続的な最大値、GC後の比較ではなく、メモリ漏れなしの証明にはしない。
