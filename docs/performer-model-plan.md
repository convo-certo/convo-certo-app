# 持ち込んだ楽譜で、好きな解釈を聴いて練習する

2026-09-24。実装候補の設計。演奏者モデルの学習・提供はまだ行っていない。

主役は「自分のMusicXMLを開き、担当を選び、伴奏と演奏する」。好きな演奏者の解釈は、その流れの中で耳から選べる追加の価値にする。最初の演奏にモデル選択や自然言語入力を要求しない。

## 現在できることと、これから学習すること

|段階|扱うもの|現在地・成立条件|
|---|---|---|
|自分のテイクの表現|照合できた音のテンポ比・相対強弱・音の長さ|`reference-profile.ts` で抽出済み。同じ譜面の対応区間で再利用する曲線。学習モデルではない|
|特定の参考演奏の解釈|録音またはMIDIと譜面の音符・フレーズの対応|未実装。音源、版、区間を固定し、人が対応づけを確認する。同じ作品の解釈を再現する段階|
|特定奏者の学習モデル|複数作品から学んだ、譜面条件付きの表現傾向|未実装。未学習の作品でも個性が伝わるかを別に評価する。人物名に固定パラメータを割り当てても達成にならない|

根拠は `app/lib/reference-profile.ts`、`app/lib/concert-engine.ts`、`app/lib/rehearsal-takes.ts`。現在のテイクは音符入力とエンジン状態の記録で、音声録音ではない。`audio-reference.ts` の音量・オンセット解析だけでは、譜面との対応や奏者の個性は確定できない。既存のFuchs参考資料リンクは学習データに使用していない。

## Metronautから取り入れる操作の整理

公式ヘルプは、再生、Listen、Tempo、Loop、Recordingを練習の近道とし、注釈などを譜面右上のToolsにまとめている。機能を一度に見せず、演奏を始めた後で必要な道具を開く構成を参考にする。これは公式説明の確認で、有料版の実機評価ではない。[Metronaut公式概要](https://community.metronautapp.com/hc/en-us/articles/360002662792-How-Metronaut-Helps-You-Practice-Sheet-Music-with-AI-An-Overview)

2026-09-24に確認した教育向けFAQは、持込譜面のインポートを未対応と案内している。同時にテンポ追従伴奏も提供しているため、追従自体を独自機能とは呼ばない。差は「カタログにない課題曲・自作曲でも、声部を含むMusicXMLから自分の練習へ持ち込める」一連の体験に置く。単旋律の譜面から伴奏を作曲する機能とは区別する。[Metronaut公式FAQ](https://metronautapp.com/teaching)

練習面の提案:

- 楽譜を中心に、再生・テンポ・繰り返しを近くに置く。入力機器は最初に準備し、詳細な追従値やログ比較は道具の奥へ置く。
- 音を変える指示は、同じ小節の「元の演奏／変更後」を聴いて採用する。例えば「軽く」を選んだときは、短い音の切りを試聴で確かめられるようにする。自由文は自分用のメモとして扱う。
- 将来の奏者モデルは「伴奏の演奏」から開き、4〜8小節を試聴して一つ選ぶ。選んだ奏者・参考演奏・適用区間だけを譜面に小さく残す。未提供モデルを選択肢に並べない。
- 演奏者の解釈の強さは一つの調整に集約し、主導権・追従感度・音量などを同時に要求しない。元に戻す操作を必ず残す。
- 次回は前の曲・担当・区間・テンポ・書き込みから再開する。練習履歴は時間、取り組んだ区間、本人のメモを中心にする。追従の照合回数を演奏の点数に見せない。

## 実装候補を支える研究

|一次資料|確認できる先例|ConvoCertoへの判断|
|---|---|---|
|[VirtuosoNet / ISMIR 2019](https://archives.ismir.net/ismir2019/paper/000112.pdf)|MusicXMLの音符特徴から、階層的にテンポ・強弱・アーティキュレーション・ペダルを生成|まず音符と表現の対応を学ぶ。音色の複製とは別。研究対象はピアノで、管楽器・合奏の有効性は未証明|
|[ScorePerformer / ISMIR 2023](https://archives.ismir.net/ismir2023/paper/000069.pdf)|譜面と演奏を対応づけ、全体・小節・拍・発音の粒度で表現を制御|「このフレーズだけ参考演奏の表現を使う」設計の候補。制御可能でも利用者が意図した音と一致するかは試聴評価が必要|
|[ATEPP / ISMIR 2022](https://archives.ismir.net/ismir2022/paper/000053.pdf)|複数のピアニストの演奏データと、奏者ラベルを加えたVirtuosoNetの実験|奏者条件付き生成の先例。録音の自動採譜誤差やレパートリーの偏りを個性として学ばない対策が必要|

上記からの設計上の推論として、初期モデルはピアノ伴奏を対象にする。Fuchsなどのクラリネット表現は、息・連続強弱・音の切り・音程変化を別に観測する研究へ分ける。ピアノのvelocityをそのまま息遣いへ置き換えない。

[ScorePerformer公式リポジトリ](https://github.com/ilya16/ScorePerformer)はCC BY-NC-SA 4.0と表記し、譜面と演奏の対応づけ・前処理コードも公開していない。製品搭載済みの部品とは扱わず、許諾または独自実装を検討する。[ATEPP公式配布元](https://github.com/tangjjbetsy/ATEPP)では既存録音の自動採譜データとして提供されている。公開論文のライセンスを、音源・データ・重み・商用利用の一括許諾と解釈しない。

## 小さく始めるデータ収集と評価

最初の目標は「名前を伏せても、同じ譜面に対する二人の解釈の違いが伝わり、合わせやすさを損なわない」。以下の規模は収集工程と評価方法を確かめるための提案であり、汎用モデルの学習に十分と証明された量ではない。

1. 協力奏者2人が、同じ4曲から各2フレーズ（各8〜16小節）を、2日間で各日2回ずつ演奏する。まずピアノMIDIと確認用の音声を対にし、同じ入力・出力条件を使う。計64テイクを出発点とする。
2. 楽譜の版・ハッシュ、声部、音符ID、反復後の演奏順、音の始まりと終わり、強弱、ペダル、機器遅延を保存する。管楽器実験を始める際は息入力と音声包絡を追加し、伴奏の回り込みを分離して記録する。
3. 音符への対応を人が確認し、誤対応・欠落・装飾音・休符を記録する。照合confidenceは補助情報にとどめ、正解ラベルにしない。欠落した音を機械補間した場合は学習対象を区別する。
4. 同じ曲の別テイクを学習側と検証側に混ぜず、3曲を開発用、残り1曲を未知曲の評価用に固定する。別日のテイクで機器・セッションの変化も確認する。曲数が少ないため統計的な一般化は主張しない。
5. 最初は同一曲の表現曲線と平均的な演奏を比較する。譜面特徴＋奏者条件の小さなモデルを試し、効果が出た場合に許諾済みデータを増やす。大きなモデルを最初から64テイクだけで学習する前提にはしない。
6. 少なくとも6人の奏者が、同じ音源・同じ基準テンポ・同じ区間で、譜面どおり／参考曲線／学習候補を順序を変えて聴く。解釈の違い、好み、合わせやすさを別々に回答し、実際に楽器で合わせた後にも選び直す。

機械評価は発音時刻・音長・強弱の誤差、急なテンポ変化、追従の復帰時間、誤った小節移動を確認する。奏者判別の正答率だけでは、良い伴奏とも未知曲への汎化とも判定しない。初期の継続条件は、未知曲で参考曲線や基準より好まれ、入りの失敗が増えず、翌週の練習でも選ばれること。結果が割れた場合は対象曲・奏者の範囲を狭めて再評価する。

## 演奏エンジンと保存への接続

構成案は `MusicXML + 奏者条件 → 音符/小節ごとの表現 → 現在の奏者入力に合わせる伴奏 → 発音`。学習モデルは曲を開いた時に基本の表現を生成し、演奏中の入り・休符・待機は現行エンジンが扱う。推論を音声スケジューラの同期処理に入れない。

現行の `ReferenceProfile` は同一譜面の曲線に限定される。学習出力を無理に同形式の「自分のテイク」として保存せず、新しい版で生成元（手動曲線／参考演奏／学習モデル）、モデル版、適用パート、検証済み楽器・音域、元データの識別子を持つ。音符単位の表現を扱うときは、現在の小節・拍の曲線への変換で失われる情報も評価する。

モデルが作ったテンポと奏者追従が競合しないよう、表現は既定のフレーズ形状、現在の演奏はその場の入りと進行を決める。上限・平滑化・無効化・譜面どおりへの復帰を設ける。譜面メモや合図待ちをモデルが上書きしない。同じ設定でも相手の今日の息・間に応答して変わることを「一度しかできない共奏」の中心にする。

## 協力者との取り決めと出典の保存

協力者には、練習記録の保存、研究解析、モデル学習、製品での利用、氏名表示、元音源の再生・共有を分けて選んでもらう。通常の練習履歴を自動的に共有学習へ回さない。許諾範囲、対象データ、保管先・期間、削除窓口、撤回後の新規学習停止と既存重みの扱いを記録する。

データごとに演奏者・録音者・提供元、譜面の版、録音日、取得経路、許諾の版、変換・対応づけの履歴を保持する。「参考にした演奏」と「本人が承認したモデル」の表示は分ける。現時点では外部録音の取得、協力者への連絡、許諾成立、学習済みモデルの提供は実施していない。
