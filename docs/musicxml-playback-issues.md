# 読み込んだMusicXMLの再生上の注意

読み込みが成功した楽譜について、現在の演奏処理で扱いに制限がある記号を検出し、演奏コントロールの「この楽譜の再生上の注意」にまとめる。持ち込みXML/MXL、カタログから開くXML、保存済み練習の再読み込みで同じ検査を行う。検査だけでは音符・再生順・元XMLを書き換えない。

検出するのは装飾音、トリル等の装飾記号とトレモロ、フェルマータ、ヘアピン、無音程の打楽器、半音より細かいalter、先頭パートの文字だけのD.C./D.S./al Codaなど。再生用sound要素がある小節の戻り指示は文字だけの指示として数えない。タイ・スタッカート・アクセント・通常の強弱・繰り返しは、この未対応記号の一覧に含めない。

各種類について検出数、パート名、譜面の小節番号を示す。長い総譜では最初の4箇所と残りの箇所数を表示して画面の肥大化を防ぐ。小節番号0、名前空間付きXML、timewise形式にも対応する。再生中の小節番号と譜面上の番号は、繰り返し等により異なることがある。

案内は折り畳める。楽譜専用ページでも確認でき、開いたときは高さを制限してスクロールできる。別の楽譜へ切り替えると前の検出結果を残さない。保存して開き直したときもXMLから再検出し、過去の注意文をファイルへ固定しない。

これは対応範囲を知らせる機能。ヘアピンには後続の実装で連続的な強弱生成を追加した（musicxml-hairpins.md）。全MusicXML記法の検査・校合・正確さの保証ではなく、一覧が空でも完全対応とは表示しない。フェルマータで小節途中の音を自動延長する処理、装飾記号から音符への展開は引き続き必要な開発項目。

## 検証

単体試験で実際のパーサーが装飾音を省略しフェルマータの音長を変更しないことと、検出で元の演奏データを変えないことを確認する。大量記号の集約、名前空間付きtimewise、対応済み記号を誤って案内しないケースも確認する。

ブラウザ試験では持ち込み・保存・リロード・楽譜専用画面・別譜面への切替を確認する。Macの実WKWebViewではフェルマータ4件を含む音列の案内を確認し、その後に読み込む別の楽譜で前のフェルマータの案内が消えることを確認する。320px幅を撮影し横のはみ出しがないことも確認した。

MusicXMLの要素の意味は[grace](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/grace/)、[fermata](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/fermata/)、[wedge](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/wedge/)を参照。アプリが何を演奏するかの判断はMusicXML仕様ではなく、現在のパーサーと音源処理の実装に基づく。

## 代表曲の構造検査（2026-09-11）

`verification-results/2026-09-10T19-13-09.243Z/xml-playback-audit.json` に6譜のファイル名・SHA-256・検出数を記録した。モーツァルトK.622第2楽章、新世界第2楽章、モーツァルト交響曲40番第1楽章、チャイコフスキー交響曲4番第4楽章・6番終楽章、くるみ割り人形の雪の場面が対象。

6譜すべてにヘアピンがあり、各パートの記号を合計すると605個。装飾・トレモロ系は合計1506個。これは全パートのXML要素数で、指揮者が行う独立した指示の数や、聴感上の影響の大きさを表すものではない。取り込み成功を合奏の再現品質とみなさず、ヘアピンの連続的な強弱と装飾・トレモロの演奏を次の実装候補として優先する根拠にする。

全体検証は同じフォルダーの `report.json`。単体225件、ブラウザ70件、Macの通常動作と画面プロセス復旧が通過した。
