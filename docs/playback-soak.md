# 実時間のループ再生試験

`node scripts/soak-playback.mjs 1800` は、既存のローカル開発サーバー（既定 `http://localhost:5188/perform`）をChromiumで開き、サンプルMusicXMLを読み込んで30分の実時間ループ再生を行う。第2引数でURLを変更できるが、localhostまたは127.0.0.1だけを許可する。サーバーは別途起動しておく。

ブラウザのタイマーやAudioContextの時計は差し替えない。音源開始を観測するためAudioBufferSourceNode.startを包むが、元のメソッドをそのまま呼び、発音時刻・バッファ・出力経路は変更しない。新しいブラウザプロファイルを使い、ユーザーの既存の保存・接続状態は読まない。マイク・MIDI入力は接続しない。

10秒ごとの記録:

- 実経過秒、AudioContextの状態と時刻、楽譜位置。
- 発音を開始した音源の累計、ended前の音源数、最大音源数。
- 取得可能な場合のJSヒープ使用量。ヒープ値を長期のメモリ漏れなしの証明にはしない。
- ページ例外とクラッシュ。

再生時計の大幅な停滞、9秒以上の区間で新規発音がない、サンプル二重奏で音源数が64を超える、不正な譜面位置、停止後に音源が残る、試験中のソース変更を失敗として記録する。この基準を全編成の最大同時発音仕様へ流用しない。音源が実際にスピーカーから聴こえるか、出力波形のクリップ、実機入力遅延、演奏者の自然さは測らない。

`verification-results/soak-<日時>/report.json` にPID、ソースハッシュ、楽譜ハッシュ、ブラウザ版、各観測値と `running` / `passed` / `failed` を保存する。runningは合格ではない。プロセスが外部から強制終了された場合はrunningのまま残り得るため、状態確認ではツールの実行ハンドルまたは実プロセスを確認する。古いrunningファイルだけで継続実行中と推定しない。

## 実行記録

- 20秒の事前確認: `verification-results/soak-2026-09-10T20-55-25.882Z/report.json`。発音開始28回、停止後の音源0、通過。30分試験の代わりには数えない。
- 30分試験: `verification-results/soak-2026-09-10T20-56-05.083Z/report.json`。実プロセスは終了コード0、レポートはpassed。実観測1800.0036秒、181サンプル、発音開始2170回、最大同時音源2。停止後は音源0、位置0、表示「準備完了」。停止直前の最終サンプルも音源0だったため、この30分試験だけで発音途中の遮断品質を証明しない。

同じフォルダーの `summary.json` に集計と元レポートのSHA-256を保存した。観測区間の音声時計／実時間の比は0.999467〜1.000454。ページ例外・時計停滞・新規発音の途切れ・音源数上限超過は検出されなかった。Chromium 145.0.7632.6、試験ソースハッシュ `131717dc0718274931a28e2fa0916a542ab7161304b2d4c18036e00e913b84f6`。試験中のソースハッシュ一致を終了時にも確認した。

JSヒープの概算は60.3MBから64.0MBへ変化し、その後は同じ値だった。ガベージコレクション後の厳密なヒープ比較、ブラウザの総RSS、Web Audioのネイティブ側メモリを測ったものではなく、メモリ漏れなしとは断定しない。

これはWeb版のサンプル二重奏による機械試験。発売条件の「人が演奏する30分セッション20本」、実オーケストラ総譜の密度、Swift/WKWebViewの30分試験とは別の証拠である。

Swift/WKWebViewでも別途30分試験が通過した。停止直前の接続中音源1から停止後0を確認した。詳細は [ネイティブ試験記録](native-playback-soak.md)。
