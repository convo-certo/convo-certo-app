# MIDIの終了信号とアーティキュレーション追従

2026-09-11。ConcertEngineで音の長さを学習するとき、note-onとnote-offを音高だけで対応付けていた。別チャンネルの同音高のnote-offで、奏者が早く音を切ったと誤認して伴奏の長さが変わった。開始時刻以前またはNaNの終了信号は、長さを更新しなくても記録中の音を消してしまい、その後の正しい終了信号を学習できなかった。Infinityでは不正な長さが上限へ丸められて学習された。

開始音のMIDIチャンネルも保存し、音高とチャンネルが一致し、終了時刻が有限かつ開始時刻より後のときだけ長さを学習して記録を消す。チャンネル省略は既存の入力との互換性のため0として扱う。不適合な終了信号では記録を維持する。

4条件（別チャンネル、開始以前、NaN、Infinity）の回帰試験は修正前に全件失敗、修正後に全件通過。試験は外へ出る伴奏音の実際の予定持続時間を確認し、不適合信号で変わらず、その後の正しい短い終了信号で短くなることを検査する。既存のチャンネル省略入力とseekでの表現リセットも含め、ConcertEngineとテイク再生の28試験が通過した。

この変更は単旋律奏者の最後に照合した音を扱う既存のモデルを保つ。多声入力の各音の独立した表現追従や、同じチャンネル・同じ音の重複発音の識別を実装したものではない。物理ClariMateでの音色・追従品質の実演確認は別途必要。

## Swift検証のポート競合

最初の全体検証 `verification-results/2026-09-10T22-59-05.072Z/report.json` はWeb・単体・ネイティブビルドまで成功したが、WKWebView試験は起動中の通常アプリが5199番を使用していて開始できなかった。既存のアプリを終了して回避せず、テスト起動時のみNetwork.frameworkの自動割当ポートを使うようにした。

LocalServerがreadyになった時点で実際のポートを公開し、画面読み込み・復旧・MIDI・印刷の接続元照合が同じ値を使用する。通常起動は引き続き127.0.0.1:5199を使い、保存済み練習のoriginを変えない。テストは従来通り非永続WKWebsiteDataStoreを使用する。
