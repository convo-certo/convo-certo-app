# 音声時計が止まった場合の復旧

演奏中・合図待ちの間、250ms間隔でWeb AudioのcurrentTimeを確認する。2秒以上変化しない場合は音源を停止し、現在の譜面位置を保持して「音声を復旧して再開」を表示する。音声状態がrunningのままでも対象になる。待機中は基準時刻を更新し、コンポーネント破棄時には監視を解除する。

復旧は奏者の操作でのみ行う。音声時計が再び動いただけでは発音しない。復旧操作でも時計が動かない場合は再度停止する。OSの出力先やドライバーを自動変更する処理ではない。

ブラウザ試験では実AudioContextのcurrentTime読み取りを固定し、状態変更イベントが発生しない停止を注入する。停止案内・位置保持・時計復帰だけでは再開しないこと・明示再開後の進行を確認する。Swiftの実WKWebViewでも同様の停止を注入する。物理機器の故障・実OS障害の再現ではない。

以前の全体試験で見られた「演奏中だが位置が進まない」失敗の原因を特定したという主張ではない。今回確認した故障状態を放置せず回復できるようにする防御である。実際の音声出力波形が無音になるだけでcurrentTimeが進む障害は検出しない。

全体検証は `verification-results/2026-09-10T19-47-52.368Z/report.json`。型検査・単体235件・ブラウザ72件・ネイティブMIDIパーサー・Swiftビルド・実WKWebView・実WebContentプロセス終了後の復旧が通過した。前の実演メモの試験修正も含む一式の検証結果であり、以前の失敗ログはそのまま保持している。
