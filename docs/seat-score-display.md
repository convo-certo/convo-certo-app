# 席と楽譜の声部

声部を分けて「あなたが入る席」を選んだ場合、譜面上の該当譜表・声部を通常の濃さ、相手の音符を35%の濃さで表示する。現在位置のハイライトと自動スクロールの対象は担当声部。相手の音符も位置指定には使える。パート全体を選び直すと通常表示に戻る。

音の高さで第1・第2奏者を推測せず、MusicXMLの声部・譜表に対応するOSMDのVoiceId/Staff.Idで判定する。描画結果に一致する音符がない場合はパート全体を通常表示し、その旨を表示する。これは単独パート譜の再浄書ではなく、相手の動きを参照できる同一パート内の表示。音符を削除せず、伴奏・移調・元のMusicXML書き出しを変えない。

ブラウザ試験は第2声部が第1声部より高い譜例、別譜表の第3声部、キーボードでの位置指定、全体表示への復帰を確認する。Swift WKWebViewでも第2声部だけのハイライトと他声部の濃度を確認する。SVGのopacity属性なので、印刷用に複製したSVGにも濃度が残る。印刷物の読みやすさは別途評価する。

席一覧は元の総譜が変わったときに計算し、演奏位置の更新ごとに全音符を走査しない。

WKWebViewで停止中の声部変更後にハイライトが再適用されない不具合を再現した。非同期描画中のloaded=false/trueがまとめて反映されると、値が変わらず描画後のeffectが動かない場合があった。描画完了のrevisionを更新し、位置・再生状態が同じでもハイライトを塗り直す。ネイティブ検証には進捗ログとタイムアウト時の声部・ハイライト状態を残す。
