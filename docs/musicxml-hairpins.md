# MusicXMLのヘアピンを音に反映する

開始・終了がそろったcrescendo / diminuendoを、各音の開始音量と持続中の音量曲線へ反映する。終点に明示された強弱を使い、なければMIDI強弱値で±24を推定する。推定値は音楽的な正解や特定演奏家の表現を意味しない。譜表とnumberで対応を判別し、次の明示的な強弱まで終点の値を保つ。

音量曲線は音符内の相対位置で保存し、繰り返し展開でも維持する。途中の音から再生した場合はその位置の強さを使う。スタッカート等で短くなった音は、その時点までの曲線で終える。曲線全体を短い音長へ圧縮しない。WebとSwiftのWKWebViewは共通処理を使用する。

未完、重複・重なり、途中に別の強弱がある区間、nienteは処理しない。再生上の注意に対応範囲を表示する。発音済みの音量曲線を演奏途中のテンポ変化で再スケジュールする処理、音色そのものの強弱変化は未実装。音量の補間であり、プロ奏者のクレッシェンドの再現ではない。

単体試験は開始音量、持続音、譜表ごとの独立性、推定終点、繰り返し、非対応区間、seekとアーティキュレーションを確認する。ブラウザ試験は人工正弦波を実Web Audioへ通して前半・後半の波形RMSを比較し、短いゲートでの音量予約も確認する。Mac試験は実WKWebViewでMusicXMLを読み込み、再生時の連続ゲイン予約を確認する。これらは実楽器での聴感評価ではない。

## 譜表と時刻による通常の強弱（追加修正）

ヘアピンがない場合も、通常の強弱は対象の譜表とdirectionのoffsetを含む時刻で解決する。以前はXMLの走査中に共有音量を変更していたため、片方の譜表への指示がもう片方へ漏れ、backup後の声部や将来時刻の指示でも強弱がずれていた。不正なsound dynamics値は無視し、直前の有効な指示を保つ。アクセントは解決後の強弱に掛ける。

回帰試験で3件を修正前に再現し、修正後に解消を確認した。収録6総譜のブラウザ上での構造検査は `verification-results/dynamics-score-audit-2026-09-11.json`。合計70,749音で音量・曲線の非有限値は0件、各譜の読み込みは今回の端末で約29〜281ms。これは単回の測定で性能保証や聴感の正確さの評価ではない。
