# 初回観察試験 — 1人45分

この原稿は実施用の準備資料。参加者への連絡・録音・課金・収集はまだ行っていない。10人で課題を見つけ、20人4週間の試験で再利用を確かめる。詳細の判断基準は[発売計画](product-launch.md)を参照する。

## 試験前

- 看板区間の正しい音符・移調・声部・反復を確認する。未確認の作品を使う場合は探索試験と明記し、完成品の品質集計に混ぜない。
- データは参加者コード、機器、操作結果、本人が提出を選んだイベントログと感想を必要範囲で残す。氏名との対応は分離する。
- 生音声・映像の記録は初期状態では行わない。必要なら目的、保存先、閲覧者、削除予定日を具体化して別に同意を得る。公開・広告への転用も別に扱う。
- 利用に不快感があれば中断できること、演奏者の技能評価ではなくアプリの評価であることを伝える。

## 進行

| 時間 | 依頼すること | 観察すること |
| --- | --- | --- |
| 0〜5分 | 最近の練習で合わせにくかった曲・区間を話す | 実際の困りごと、現在の代替手段、練習頻度 |
| 5〜10分 | アプリを開き、自分の席で60秒演奏する | 初回成功時刻、迷い、接続・移調失敗、必要な支援 |
| 10〜18分 | 4〜8小節を3回練習し、一度わざと間違える | 復帰、伴奏に合わせさせられる感覚、ループの使いやすさ |
| 18〜25分 | 長い休符から入り、別パートへ受け渡す | 自分が主導しないときの自然さ、誤った全体追従 |
| 25〜30分 | 席を移動し、ホルンを追加し、比較する | 空間の聴き分け、用途、音量差や重複サンプルへの反応 |
| 30〜35分 | 設定を保存し、閉じ、再開する | 復元できる範囲、データ消失、不意の発音。未実装なら失敗として記録 |
| 35〜40分 | 固定テンポ版と追従版を順序を変えて比較する | どちらを使うかと理由。条件・順序を記録 |
| 40〜45分 | 次回使う場面、不要な機能、価格への反応を話す | 「良かった」より具体的な次の練習予定を聞く |

最初の5分は操作を教えない。支援が必要ならその時刻と内容を記録し、支援あり成功として扱う。故障を奏者のせいにしない。追従が崩れた箇所は譜面上の位置と実際の入力を照合し、推定のconfidenceを正解として採点しない。

## 1セッションの記録欄

- 参加者コード / 実施日 / アプリ版:
- OS・ブラウザ / CPU / 音声出力 / 有線・無線:
- 楽器・移調 / MIDI機器・FW・公式アプリ版 または マイク:
- 作品ファイルのSHA-256 / 担当パート・声部 / 区間:
- 接続一覧が出た時刻 / 最初の入力受信 / 最初の正しい照合 / 60秒共奏完了:
- 手助けの回数・内容 / 中断理由:
- 誤った譜面位置 / 復帰までの拍数 / 音切れ / 不意のテンポ変化:
- 固定テンポ・追従の比較順 / 好み・理由:
- 空間ON/OFFの比較順 / 好み・理由:
- 次回使う作品と場面 / 代替サービス / 価格提示条件と反応:
- 保存したログの所在 / 削除予定日 / 記録範囲の同意:

## 継続試験

初回の後は、本人が同意した方法で週ごとの利用を確認する。ローカルのみで扱う場合は、本人が選んだ集計を提出する。生音声や個人の楽譜を自動アップロードする仕組みは前提にしない。起動回数と、実際に練習した回数・時間を分ける。問い合わせ・督促の直後の利用は自発利用と分ける。

週4で使用を続けた理由・やめた理由を聞く。入力方式ごと、参加経路ごとに分けて記録する。友人・開発者本人の利用だけで販売へ進めない。小人数の結果を一般市場の割合として宣伝しない。

## アプリ内で残せる実演メモ（2026-09-11）

「共奏のチューニング」でテイクを記録して終了すると、「次の練習のためにメモを残す（任意）」を開ける。次も使いたいか（使いたい・まだ分からない・今のままでは使わない）と、良かった点・困った小節・次に試すことを2,000文字まで記録できる。初期値は未回答で、空欄を好意的回答へ変換しない。

「テイクの記録を保存」は音符入力、設定、短い感想とともに `experience.reuse` / `experience.notes` をJSONへ含める。画面を閉じると未保存テイクは消えることを画面内で伝える。自動送信・氏名収集・録音は追加しない。本人が提出を選んだファイルだけを試用の材料にする。

この意向は実際の翌週の利用や支払いではない。位置一致回数もシステムの照合結果であり、演奏の正誤や自然さの採点ではない。実際の再利用と有料利用は引き続き別に確認する。

ブラウザの回帰試験では実際にテイクを終了し、未回答の初期状態、感想の編集、A/B計算後のJSONダウンロード内容を確認する。390px幅の表示も撮影し、横のはみ出しがないことを確認した（`verification-results/take-experience-mobile.png`）。

全体試験 `2026-09-10T19-41-20.539Z` は既存の音声復旧試験で再生位置が進まず失敗した。新しいテイク試験は通過。音声復旧試験の直後の単独実行は通過したが、原因特定・修正の証拠にはならないため、この失敗記録を保持する。

再検証 `2026-09-10T19-42-54.338Z` は型検査・単体235件・ブラウザ71件が通過し、Mac試験が新しい操作の開始待ちで失敗した。停止直後にまだ無効な記録ボタンを押していた試験側を修正し、ボタンが有効になってからクリックするよう変更。続く `npm run native:build && npm run native:test` が通過し、実WKWebViewで未回答・再利用意向・日本語メモの編集まで確認した。全体レポートの失敗を書き換えず、工程ごとの再検証結果として扱う。
