# 保存した吹奏テイクを再び比較する

「共奏のチューニング」で記録したテイクを「テイクの記録を保存」から書き出し、後日「保存したテイクを開く」から戻せる。旧形式のJSONも感想・入力の閲覧用に開けるが、楽譜の演奏条件を持たないものは比較・表現の作成を無効にする。保存時と同じ譜面・移調・担当を先に選ぶ。テイク自体にはMusicXMLを含めないため、譜面と設定は練習ファイルで別途保存する。

読み込みは音符入力、当時の追従設定・応答、感想・メモを復元する。現在の設定や演奏位置を変更せず、自動再生しない。「同じ入力でA/B比較」で当時の設定と現在の設定の応答をシミュレーションできる。音声の録音・再生ではなく、正解位置を人が付けた評価でもない。

16MB、入力・状態各20000件、約10分までの記録を検査する。配列の時間順序、音高、設定値、譜面・担当の一致などを確認し、不正なファイルでも表示中のテイクを置き換えない。ファイル読み込み中に曲を変更した場合は結果を破棄する。同じIDの再読み込みは重複表示せず更新する。画面内の保持は最新8件までで、自動保存・外部送信は行わない。

単体試験は過去形式の復元、再比較の一致、別譜面・席、破損・件数超過を検証する。ブラウザ試験は実際のダウンロード→画面再読み込み→ファイル選択→感想の復元・比較・不正ファイル拒否を行う。ネイティブsmokeも実WKWebViewで書き出し内容をファイル入力へ戻し、メモ・回答の復元と自動再生なしを確認する。

実演者の評価結果を生成する機能ではない。記録された合成入力を実演と呼ばず、任意回答の空欄を肯定的な感想に変換しない。

検証結果: `verification-results/2026-09-10T22-16-35.675Z/report.json` の8工程が通過（単体255件、ブラウザ80件）。実WKWebViewでの再読み込み・メモ復元も通過。梱包したDMGをコピーした先でもWKWebViewと中断復旧の確認を行い、`distribution/package-report.json` に保存した。

## 比較する楽譜の条件

旧scoreKeyは音高・開始拍・長さ・パートID等だけを含み、強弱・テンポ・拍子が違っても一致していた。新しいテイクはscoreContextも記録する。ParsedScore全体をオブジェクトのキー順に依存しない形へ整え、長さと2種類の32bitチェックサムを保存する。配列の順序は保ち、テンポイベント、拍子、展開順、担当、音の強弱・切り方・強弱曲線も違いとして検出する。設定の保存先に使う既存scoreKeyは変更しない。

このチェックサムは取り違えを検出するためのもので、署名や改ざん防止、実演の真正性を保証するものではない。古い記録に現在の譜面の条件を後付けして確認済みにしない。

読み込み時に加えて、再比較とテイクから表現を作る処理でも照合する。旧形式は感想・入力を保持して開き、比較できない理由を表示する。新形式の不一致は現在のテイクを変更せず拒否する。

演奏条件の照合追加後の一括検証: `verification-results/2026-09-10T22-21-20.254Z/report.json`。単体265件・ブラウザ80件、実WKWebViewと中断復旧を含む8工程が通過。DMGコピー先の起動と復旧も通過。旧形式の表示・比較無効化、条件不一致時の元テイク保持をブラウザで検証し、WKWebViewでも不一致拒否と元メモ保持を確認した。
