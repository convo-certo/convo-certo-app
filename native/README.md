# ConvoCerto macOS preview

Swift / AppKit / WKWebViewによるWebアプリ版。Webビルド・楽譜・音源を.appに同梱し、127.0.0.1の空きポートを使うアプリ内HTTPサーバーから読み込みます。NodeやViteを実行時に必要としません。MIDI入力はCoreMIDIからWKWebViewへ渡し、Web版と共通の受信・追従処理を使用します。ブラウザ版とデータ保存領域は別です。

## ビルドと起動

macOSとSwiftコンパイラが必要です。今回の環境ではCommand Line ToolsのSwift 6.1.2でビルドしています。

```sh
npm run build
npm run native:build
open build/native/ConvoCerto.app
```

開発用のアドホック署名です。Developer ID署名、公証、配布・更新・アンインストールの製品対応は未完了です。`/Applications`へのインストールは行っていません。生成物は`build/native`に置きます。

## 実際のWKWebViewを用いる検証

```sh
npm run native:unit
npm run native:test
npm run verify:release
```

`native:test`は実アプリのWKWebViewで、同梱Mozart XMLの取り込み、サンプル音源の準備、SVG譜面表示、IndexedDB保存、楽譜専用ページ、再生・停止を検査します。さらに試験専用のCoreMIDI仮想ソースを作り、音符・CC11、複数パケット、ランニングステータス、切断・再接続をReactの表示まで検証します。試験専用の一時データストアを使い、通常の練習保存を変更しません。試験用のJavaScriptメッセージ窓口は`--smoke-test`起動時にだけ登録します。検証結果はJSONとプロセス終了コードで返り、60秒でタイムアウトします。

`verify:release`はソースと配布素材のSHA-256、環境、各工程の結果・ログを`verification-results/<timestamp>`へ保存します。型検査→単体テスト→Web本番ビルド→ブラウザ試験→Swiftビルド→WKWebView試験を順番に実行し、失敗時に止まります。一般発売への適合は別であり、機械検証が成功しても`report.json`の`saleReady`をtrueにしません。

## まだ検証・実装が必要なもの

- ClariMate実機での吹奏・遅延・連続利用。CoreMIDIとWeb画面の入力連携と仮想機器の切断復旧は自動検証済みです。今回のMacではClariMate Series II MIDI Outの存在も確認しましたが、実機演奏の品質は未検証です。
- マイク・カメラの許可と解除、スリープ、USB切断・再接続、音声デバイスの切り替え、表示プロセス再起動後の実機長期運用。表示プロセスを強制終了して保存済み練習へ復旧する自動試験は追加済みです。
- 保存先の権限エラーの実操作は未確認。印刷・保存のキャンセルと画面復帰は通常起動のアプリをCUAで操作して確認しました（[検証記録](../docs/native-dialog-verification.md)）。印刷は専用WKWebViewで各SVGページをPDFへ変換し、A4に配置してPDFKitの印刷処理へ渡します。自動試験でモーツァルトのページ数一致とPDF出力を確認し、先頭ページの画像を目視確認しました。実プリンターへの出力や全譜面の校合は未検証です。MusicXMLと練習ファイルの書き出しはWKDownloadとNSSavePanelに接続しました。自動試験では専用一時フォルダへ実際に書き込み、Web側のBlobとSHA-256を照合します。ファイル読み込みにはNSOpenPanelを実装していますが、実際の人によるダイアログ操作検証は未実施です。
- 起動時間、長時間の音切れ、CPU・メモリ、実際の音の品質。再生テストはノードの開始と演奏位置を確認するもので、聴感や物理出力の測定ではありません。
- ポート競合時の回復、セキュリティレビュー、製品署名と公証、販売と顧客サポート。

visionOSアプリではありません。現在の対象はmacOSです。

## MIDIの境界

入力のみを実装しています。SysEx、MIDI出力、MIDI 2.0固有の表現は対象外です。初期化・機器一覧・選択・音符イベントをWeb MIDI互換の最小インターフェースで渡します。ブリッジはアプリ内の正しいホスト・ポート・主フレームからの要求だけを扱います。画面の再読み込みでは入力を切断し、機器を選び直す必要があります。機器の切り替え前に受信キューへ入ったデータは世代番号で破棄します。CoreMIDIの時刻は現在JSの受信時刻へ変換するため、物理入力遅延の測定は別途必要です。

仮想ソース作成と信号注入は`--smoke-test`限定です。通常起動ではこれらの要求を処理しません。実際の機器へのMIDI送信は実装していません。

## 練習ファイルを持ち運ぶ

「この練習を保存」のあと、マイ楽譜の「練習ファイルを書き出す」で`practice.convo.json`を保存します。別のブラウザやMacアプリでは「練習ファイルを読み込む」で追加してから、曲名を押して再開します。MusicXML、保存済みの席・移調・テンポ・区間・配置を含みます。機器の権限や接続は移しません。読み込み時は形式・版・数値・パート・音源割り当てを検査し、不正なら既存ライブラリへ書き込みません。既存項目は上書きせず、新しい項目を追加します。ブラウザ間の往復を自動検証しています。

印刷のAPIはAppleの[WKWebView PDF生成](https://developer.apple.com/documentation/webkit/wkwebview/createpdf(configuration:completionhandler:))とPDFKitを使用します。WebViewの直接印刷はこの環境で終了しなかったため採用せず、ページごとの非同期PDF生成後に印刷します。印刷用ビューにはMIDI等のブリッジを渡さず、スクリプト・外部読込を制限します。PDF生成は30秒で打ち切り、再試行可能です。

## 開発プレビューDMG

全体検証が成功した後、その実行のレポートを指定する。

```sh
npm run native:package -- verification-results/<run>/report.json
```

通常起動中のConvoCertoは終了してから実行する。検証したソース・アプリ本体と現在のハッシュが一致しない場合は梱包しない。`build/distribution/ConvoCerto-preview-*/`にDMG、SHA-256を含むJSONレポート、工程ログを作る。DMGを読み取り専用でマウントし、一時フォルダーへコピーしたアプリで署名検査と実WKWebViewの全smokeを行う。`/Applications`の既存アプリや通常の練習データは変更しない。

DMGにはアプリ、Applicationsへのリンク、導入・更新・削除の説明を含める。開発用アドホック署名のままであり、公証済みの一般配布物ではない。ダウンロード後のGatekeeper、別Mac・別OS・Intelでの起動、自動更新、素材の全配布権利は、このパッケージ検証で証明しない。公開・送付は行わない。

ビルドの最低OS指定はmacOS 13.0とし、Info.plistと実行ファイルのLC_BUILD_VERSIONの一致を梱包時に確認する。これはビルド条件であり、macOS 13での動作確認済みという意味ではない。実際に検証したOS・CPUはパッケージレポートに記録する。現在の環境ではarm64版を作成しており、Universal Binaryではない。

## 画面プロセス終了からの復旧

画面のWeb Contentプロセスが終了した場合は、アプリ全体を終了せず、「画面を開き直す」「終了」の選択を表示する。開き直すとマイ楽譜から保存済み練習を選べる。未保存の編集や直前の演奏位置は復元しないことを案内し、MIDIを切断する。マイク・MIDIの再接続と伴奏の再開はユーザーの操作で行う。

`npm run native:recovery`は専用の非永続データストアを使って練習を保存・演奏し、OSのLaunch Servicesの所属情報でテスト用Web Contentを一意に特定してSIGKILLを送る。同じ所属の対象を一意に特定できない場合は強制終了しない。通常のユーザーデータや他のブラウザのプロセスは対象外。復旧のネイティブボタンを試験用に押し、保存済み練習と設定の復元、MIDI切断、非自動再開、手動演奏開始を確認する。

全体検証とDMGコピー後の検証にも含める。物理マイクを取得中の終了、保存の書き込み途中、印刷途中、OS自体のクラッシュ、ディスク破損からの回復は別の未検証条件。
